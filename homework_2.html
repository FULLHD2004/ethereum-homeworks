01 · Toy elliptic-curve encryption

The recipient's private key is k, and the public key is Q = kG. The sender chooses an ephemeral value r, publishes C₁ = rG, and computes a shared point S = rQ. The receiver computes the same point as S = kC₁. Both sides turn S into a deterministic XOR mask for the message bytes. This is an educational construction, not a secure encryption standard.

ECC key generation — repeated addition

Point addition uses modular inverses modulo 17. The point at infinity is shown as O. Because 9G = O, k = 9 produces O, and keys separated by multiples of 9 produce the same public point.

Steps of the educational algorithm

  1. Key generation: choose private k and publish Q = kG.
  2. Encryption: choose ephemeral r, compute C₁ = rG and S = rQ.
  3. Message masking: derive a toy byte mask from S and XOR it with UTF-8 plaintext bytes.
  4. Decryption: compute S = kC₁; XOR the same mask with ciphertext to recover the message.

Why it works: rQ = r(kG) = k(rG) = kC₁.

02 · Caesar cipher

Each English letter is shifted by a fixed amount s modulo 26. Encryption: Eₛ(x) = (x + s) mod 26. Decryption: Dₛ(y) = (y − s) mod 26. Upper/lowercase and punctuation are preserved.

03 · Statistical cryptanalysis of Caesar

Frequency-based attack

For every shift candidate s = 0…25, decrypt the ciphertext and compare its observed letter counts with expected English frequencies. The lowest chi-square (χ²) score is selected: χ² = Σ (observed − expected)² / expected. Larger, representative English samples generally give more reliable estimates.

04 · Recover the toy ECC private key

The attacker knows the public parameters G and the public key Q, and tests dG for each candidate d ∈ {1,…,8}. A match reveals the private scalar modulo the order of G. The same candidate can compute dC₁ to decrypt the recorded ECC ciphertext.

Encrypt a message in the Toy ECC tab first. Then click “Brute-force private key” to recover the key and message.

Can the message be decrypted without recovering the ECC private key?

Why this experiment is included: The optional part of the homework asks whether a weakness could come from the toy encryption design itself, rather than only from its small private-key space. This experiment demonstrates such a separate weakness in our custom XOR mask.

What the attacker knows: The ciphertext and the first character of the original message (for example, H in Hello). The attacker does not need to know the private key. Enter that known first ASCII character below after encrypting a message.

What happens when you click the button: XORing the first ciphertext byte with the known first plaintext byte reveals the first mask byte. In this program, all later mask bytes follow a predictable formula, so the attacker can reconstruct the full mask and decrypt the remaining ciphertext.

What this proves: Even if an attacker could not brute-force the ECC private key, this particular homemade masking method would still leak the message when its first byte is known. It is a flaw in the toy XOR design, not an attack that breaks secp256k1 or all ECC encryption schemes.

Technical detail: the byte mask is (B + 73i + 11 floor(i/2)) mod 256, with B = (31S.x + 17S.y) mod 256. At position zero, B = ciphertext[0] XOR plaintext[0]; once B is known, every mask byte can be calculated.

Encrypt a message with a known first ASCII character, then run this attack.

A wrong first character generates an incorrect candidate plaintext. The demonstration assumes the attacker knows the true first ASCII character; it does not claim universal ciphertext-only recovery. Once the first mask byte is learned, the rest are predictable because of the custom formula.

Why the attack is possible

Since G has order 9, this example has at most 8 nonzero private scalars to test when the secret is chosen from 1…8. In contrast, properly generated secp256k1 keys operate in a subgroup of approximately 2²⁵⁶ elements. General discrete-log algorithms such as Pollard's rho still require on the order of 2¹²⁸ curve operations, which is computationally infeasible in the classical model.

Separating weaknesses: the key-space search succeeds because the group/order and chosen scalar range are tiny. Independently, this homemade XOR masking mechanism would be insecure even with a larger curve if reused or badly derived. The fixed deterministic mask also gives neither semantic security nor integrity: a known plaintext byte reveals the whole mask, and ciphertext bytes can be modified without detection. A real system uses a vetted protocol such as ECIES/HPKE with a proper KDF, authenticated encryption, fresh ephemeral randomness, and point validation.

Similarities

  • Both transformations can recover the original message when the correct key information is known.
  • Both can be tested by trying candidate keys when the candidate set is small.
  • Both toy constructions have trivially recoverable secrets in this exercise.

Differences

  • Caesar is symmetric; ECC key agreement uses a public/private pair plus a fresh ephemeral scalar.
  • Caesar directly substitutes letters; the hybrid computes a shared curve point before masking bytes.
  • Frequency analysis exploits language redundancy; toy ECC brute force exploits a tiny key/group space.

Effectiveness and limitations

Letter frequencies: expected English percentages are approximately E 12.70%, T 9.06%, A 8.17%, O 7.51%, I 6.97%, N 6.75%, and so on. Frequency-based χ² scoring usually works better on longer standard English plaintext. It can fail for short samples, deliberately unusual writing, other languages, and text with atypical letter distributions.

Exhaustive search: because Caesar has only 26 keys, trying all candidates always includes the true key, although identifying the right plaintext needs human inspection or a scoring rule. Bigram/trigram scoring can improve automated ranking for small samples, provided a suitable language corpus is available.

ECC: brute-force matching of public points does not use letter frequencies or natural-language assumptions. It finds the scalar algebraically. With real secp256k1-sized secret keys, the corresponding attack is not practical; implementation flaws, weak random number generation, nonce reuse, invalid-point handling, or custom unsafe encryption mechanisms are separate risks.

Pseudocode of the two attacks

CAESAR ATTACK:
for s from 0 to 25:
    candidate = decrypt_caesar(ciphertext, s)
    score[s] = chi_square(candidate, english_frequencies)
return shift with minimum score

TOY ECC ATTACK:
for d from 1 to 8:
    if scalar_multiply(d, G) == Q:
        shared_point = scalar_multiply(d, C1)
        return xor_decrypt(ciphertext, shared_point)

Final security conclusions

Homework 1 versus real secp256k1: this lab uses the same short Weierstrass equation shape y² = x³ + 7, but the tiny field modulo 17 and base point of order 9 are not standard secp256k1. There are only eight nonzero scalars in the subgroup, so exhaustive recovery is essentially immediate. A restricted scalar range on actual secp256k1 would also enable enumeration, but its points and arithmetic would be different.

Independent attack surfaces: the public-key brute-force attack needs the eight-element group/key range and does not use any plaintext. The mask attack needs one known first plaintext byte but never performs elliptic-curve scalar search; it works because the toy XOR mask has a predictable byte sequence. These are separate design weaknesses. For properly chosen full-size secp256k1 keys, even generic discrete-log algorithms such as Pollard rho need roughly 2¹²⁸ operations in the classical setting, provided the implementation and associated encryption scheme are secure.

Statistical contrast: chi-square ranking of Caesar exploits letter-frequency structure, so the amount and language of the ciphertext influence reliability. ECC public-key enumeration compares curve points directly, so the plaintext language and length do not affect whether the correct scalar is found.
