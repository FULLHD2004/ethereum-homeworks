EXERCISE 1

Deriving Welford’s Recurrence Formulas

Suppose observations x1, …, xk arrive one at a time. Let Mk be their mean and SSk their sum of squared deviations from that mean:

Mk = (1/k) ∑i=1k xi    and    SSk = ∑i=1k (xi − Mk)2.

We seek updates that use only the previous count, mean, and sum of squares—without storing earlier observations.

Step 1 — Recurrence for the mean (Knuth’s update)

When the next observation xk arrives, separate it from the previous sum. Writing δ = xk − Mk−1,

Mk = ((k − 1)Mk−1 + xk) / k = Mk−1 + δ/k.

Consequently, the difference between the new observation and the updated mean is

xk − Mk = δ(1 − 1/k) = δ(k − 1)/k.

Step 2 — Recurrence for the sum of squares (SS)

Split the new squared-deviation sum into the first k − 1 observations and the new observation:

SSk = ∑i=1k−1(xi − Mk)2 + (xk − Mk)2.

For each earlier observation, substitute xi − Mk = (xi − Mk−1) − δ/k. Expanding squares, the cross term disappears because the deviations from the old mean add to zero:

∑i=1k−1(xi − Mk−1) = 0.

Therefore,

SSk = SSk−1 + (k − 1)δ2/k2 + δ2(k − 1)2/k2
= SSk−1 + δ2(k − 1)/k.

Since xk − Mk = δ(k − 1)/k, we obtain the standard Welford recurrence:

Sum-of-squares update
SSk = SSk−1 + (xk − Mk−1)(xk − Mk).

Step 3 — Recurrence for variance

The unbiased sample variance, for k ≥ 2, is sk2 = SSk / (k − 1). Substituting the SS update gives

sk2 = [(k − 2)sk−12 + (xk − Mk−1)(xk − Mk)]/(k − 1),   k ≥ 3.

At k = 2, set s22 = SS2. Alternatively, retain SS throughout and divide once at the end. If instead variance is defined with divisor k (the descriptive or population-form variance), then vk = SSk/k, and

vk = [(k − 1)vk−1 + (xk − Mk−1)(xk − Mk)] / k.

Step 4 — The core algorithm

Initialize count = 0, mean = 0, and ss = 0. Then execute these three update statements for each incoming observation, after incrementing the count:

Python implementation

count += 1
      old_mean = mean; mean += (x - mean) / count
      ss += (x - old_mean) * (x - mean)

After all observations, mean is the sample mean and ss / (count - 1) is the unbiased sample variance (when count >= 2).

Python function

In this project, the welford() function calculates the sample mean and variance of a list of scores using Welford’s algorithm. It can be reused for every hacker without rewriting the same code, making the program simpler, cleaner, and more efficient.

def welford(scores):
    count, mean, ss = 0, 0.0, 0.0
    for x in scores:
        count += 1
        old_mean = mean; mean += (x - mean) / count
        ss += (x - old_mean) * (x - mean)
    if count < 2:
        raise ValueError("At least two scores are needed for sample variance")
    return mean, ss / (count - 1)
EXERCISE 2

Sampling Mean and Variance

1. Choose a fixed probability distribution

Let every penetration attempt receive an independent, uniformly distributed integer score from 0 through 10 inclusive. Thus P(X = j) = 1/11 for j ∈ {0, 1, …, 10}. The distribution is identical for every attempt and every hacker.

Theoretical population meanμ = (0 + 1 + ⋯ + 10)/11 = 5
Theoretical population varianceσ² = (1/11)∑(j − 5)² = 10

The second result follows because ∑j=010(j − 5)2 = 110 and 110/11 = 10.

2. Simulate m hackers, with n systems each

Each hacker receives a sequence of n scores. We use Welford’s recurrence to calculate that hacker’s sample mean and unbiased sample variance. Across m hackers, compute:

Average of sample means = (1/m) ∑h=1m Mh
Average of sample variances = (1/m) ∑h=1m sh2

3. Python code for the full experiment

Uses Python’s standard library only. This Python code runs the complete simulation. It generates random scores for each hacker, calculates their sample mean and variance using Welford's algorithm, and computes the averages across all hackers. Finally, it compares these results with the theoretical mean and variance to check how closely the simulation matches the expected values.
import random

def welford(scores):
    count, mean, ss = 0, 0.0, 0.0
    for x in scores:
        count += 1
        old_mean = mean; mean += (x - mean) / count
        ss += (x - old_mean) * (x - mean)
    if count < 2:
        raise ValueError("n must be at least 2")
    return mean, ss / (count - 1)

m, n = 1000, 100
rng = random.Random(2026)  # Reproducible results
sample_means, sample_variances = [], []

for _ in range(m):
    scores = (rng.randint(0, 10) for _ in range(n))
    avg, variance = welford(scores)
    sample_means.append(avg)
    sample_variances.append(variance)

mean_of_means = sum(sample_means) / m
mean_of_variances = sum(sample_variances) / m

mu, sigma_squared = 5, 10
print(f"Average sample mean:     {mean_of_means:.4f}")
print(f"Theoretical mean:        {mu:.4f}")
print(f"Average sample variance: {mean_of_variances:.4f}")
print(f"Theoretical variance:    {sigma_squared:.4f}")

The Python code and the HTML simulation may give different results because they generate random numbers differently. However, both use the same probability distribution, formulas and statistical calculations so the results should be similar.

DISCUSSION & CONCLUSIONS

What Do the Comparisons Show?

For each hacker, the sample mean is a random quantity, so it usually differs from 5. Likewise, an individual sample variance usually differs from 10. However, when we average these estimates over many independent hackers, their overall averages tend to be close to the theoretical values.

Estimator Expected value Interpretation
Sample mean, Mh E[Mh] = μ = 5 Unbiased for the population mean
Sample variance, sh² E[sh²] = σ² = 10 Unbiased for the population variance when divided by n − 1
Variance of sample mean Var(Mh) = σ²/n = 10/n Larger samples yield more precise estimates of μ
Average of m sample means Variance = σ²/(mn) = 10/(mn) Averaging independent estimates reduces fluctuation

Explanation of Statistical Results

1. The sample mean represents the average score obtained by a single hacker across n penetration attempts. Each hacker may obtain a different sample mean because the scores are randomly generated. However, the expected value of the sample mean is equal to the theoretical population mean (μ = 5). This means that the sample mean is an unbiased estimator: when we repeat the experiment many times, the average of the sample means tends to approach 5.

2. The sample variance measures how much a hacker's scores differ from their sample mean. A higher variance indicates that the scores are more spread out, while a lower variance indicates that they are closer together. By dividing the sum of squared deviations (SS) by n − 1 instead of n, we obtain an unbiased estimator of the population variance. Therefore, the average of the sample variances across many independent hackers tends to approach the theoretical variance (σ² = 10).

3. The variance of the sample mean measures how much the average scores of different hackers can vary from one another. Unlike the sample variance, which measures differences between individual scores, this quantity measures differences between sample means. As the number of attempts (n) increases, the variance of the sample mean decreases. This means that hackers performing more attempts generally obtain sample means closer to the theoretical mean, making their estimates more precise.

4. This calculation measures how much the overall average of the sample means can vary when the entire simulation is repeated. Instead of using the results of a single hacker, we combine the sample means of all m hackers. Because each hacker performs n independent attempts, the overall average is based on mn observations. Increasing the number of hackers (m) or the number of attempts per hacker (n) reduces the variance of this overall average. As a result, the estimated population mean becomes more stable and reliable.

Why the n − 1 denominator matters

If we instead computed each sample variance as SS/n, its expected value would be ((n − 1)/n)σ², which is below the theoretical variance. Using SS/(n − 1) corrects this downward bias. The distinction is especially important when n is small.

Why this is useful in inferential statistics

In real applications, the population parameters μ and σ² are usually unknown. Statistical inference uses finite random samples to estimate those unknown values. This exercise illustrates unbiased estimation (correct on average across repeated samples), sampling variability (different samples lead to different answers), and the law of large numbers (averages of independent estimates stabilize as the number of repetitions grows).

Final conclusion. Welford's algorithm is an efficient way to calculate the mean and variance. Instead of storing all the scores and calculating everything at the end, it updates the results every time a new score is generated. This saves memory and helps avoid calculation errors caused by limited numerical precision. The simulation shows that the average of the sample means gets close to the theoretical mean (μ = 5), while the average of the sample variances gets close to the theoretical variance (σ² = 10). As the number of hackers increases, these averages generally become closer to the theoretical values because random differences tend to balance out. This is useful in inferential statistics because it shows how we can use sample data to estimate the mean and variance of a larger population.

Assumptions: All scores are generated independently using the same probability distribution, where each integer from 0 to 10 has an equal chance of being selected. Each hacker must perform at least two attempts to calculate the sample variance. Since the scores are random, the simulation results may not exactly match the theoretical mean (5) and variance (10). However, with more independent hackers, the averages generally become closer to these theoretical values.
