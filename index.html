4. How does point addition work?

For distinct points P=(x₁,y₁) and R=(x₂,y₂), calculate the slope:

λ = (y₂ − y₁) · (x₂ − x₁)⁻¹ mod 17

If the points coincide, use point doubling:

λ = (3x₁²) · (2y₁)⁻¹ mod 17

The resulting coordinates are:

x₃ = λ² − x₁ − x₂ mod 17
y₃ = λ(x₁ − x₃) − y₁ mod 17

The symbol ⁻¹ denotes the multiplicative inverse modulo 17, not ordinary division.

If P + (−P) = O, the result is the point at infinity O, the identity element of the group.

6. Conclusions

One-way function: given k and G, calculating Q = kG is easy. However, for appropriately chosen cryptographic curves and groups, recovering k from Q is computationally difficult (the Elliptic Curve Discrete Logarithm Problem, ECDLP).

Not a hash function: a cryptographic hash should resist collisions and preimage attacks and typically exhibit a strong avalanche effect. Scalar multiplication, instead, is a group operation: (k+1)G = kG + G. The avalanche effect is not a defining requirement, and within a subgroup of order n, the mapping is injective for k in 1…n−1.

Limitation of the toy example: the initial base point G = (1, 5) has order 9 and 9G = O. Other points may have different orders, but all are insecure on such a small curve. Ethereum uses secp256k1 with a vastly larger group. This program is for learning only, not for generating real keys.

HOMEWORK 2 · WALLET RESEARCH

From Wallet Seed to Ethereum Address

Ethereum wallets combine multiple cryptographic techniques because each serves a different purpose. BIP-39, BIP-32, and BIP-44 manage and derive keys; secp256k1 provides public-key cryptography and digital signatures; Keccak-256 generates address hashes; and EIP-55 helps detect address transcription errors. 1. BIP-39 — key generation and encoding: converts randomly generated entropy (that should be unpredictable and uniformly generated) into a mnemonic phrase that is then converted into a 512bit seed (pseudorandom  outputs) using PBKDF2-HMAC-SHA512.  2. BIP-32 — key derivation: multiple private and public keys can be derived deterministically from a single seed, so that one recovery phrase can restore multiple wallet accounts.  3. BIP-44 — key derivation and organization: defines a standard structure for organizing derived keys, it says how cryptocurrency wallets organize and derive multiple accounts from a single seed. BIP-44 itself defines paths rather than a randomization algorithm.  4. secp256k1 — public-key cryptography: is used to generate a public key from a private jey through scalar multiplication, this operation is computationally difficult to reverse. Security relies on the difficulty of recovering the private key from the public key.  5. Keccak-256 — hashing: is a cryptographic hash function used by Ethereum to generate wallet addresses from public keys. It takes the 64 bytes of the public key and produces a fixed length output of 256 bits, then it takes the last 160 bits of this hash to create the wallet address. Hash outputs should appear uniformly distributed, with approximately 50% zeros and 50% ones across many samples. Changing one input bit should change approximately half of the output bits on average (avalanche effect).  6. EIP-55 — checksum encoding: errors detector when copying or typing Ethereum addresses, it determines which letters should be upper or lowercase. The Ethereum wallet pipeline uses several cryptographic techniques because each algorithm has a different purpose, and no single algorithm can efficiently perform all the required operations. BIP-39, BIP-32, and BIP-44 are used for seed generation, key derivation, and wallet organization. secp256k1 generates public keys from private keys and enables digital signatures. Keccak-256 is used for hashing public keys to generate Ethereum addresses, while EIP-55 provides a checksum to detect typing errors in addresses.  Combining them allows Ethereum wallets to generate, organize, recover, and use cryptographic keys securely.  The development of cryptographic technologies began with RSA in 1977, introducing public-key cryptography, followed by SHA-2 / SHA-512 in 2001, used for secure hashing. Later, BIP-32 (2012) introduced hierarchical deterministic wallets, BIP-39 (2013) introduced mnemonic recovery phrases, and BIP-44 (2014) standardized wallet derivation paths. In 2015, NIST standardized SHA-3, based on Keccak, and in 2016, EIP-55 introduced mixed-case checksum addresses for Ethereum. SHA-512 belongs to the SHA-2 family, while Keccak is the foundation of SHA-3. However, Ethereum's Keccak-256 differs from the standardized SHA3-256 because of its padding and domain-separation conventions.
